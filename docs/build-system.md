# Система сборки

## `build32.ps1`

Скрипт собирает ядро, пользовательские программы и итоговый FAT32-образ.
Он разделён на несколько логических частей.

### Запись чисел в образ

Функции `Set-UInt16` и `Set-UInt32` записывают значения little-endian в
массив байтов. Они используются при создании FAT и directory entries.

### Сборка C-ядра

`Build-KernelImage`:

1. компилирует `pm32/kernel/core/core.c` через `wcc386`;
2. линкует LX-образ по адресу `0x10000`;
3. читает object table и page map LX;
4. извлекает загруженные секции в плоский `kernel-core.bin`.

Нельзя возвращать поиск и замену адресов по всему машинному коду. Такое
псевдорелоцирование уже повреждало инструкции ядра и приводило к triple fault.

### Сборка пользовательских программ

`Build-UserProgram` компилирует файл `pm32/user/<name>.c`, линкует его вместе с
`build32/userlib.obj` по виртуальному адресу `0x20000` и извлекает плоский BIN.
Reserved area FAT32 занимает 128 секторов, что оставляет до 127 секторов для
`SYSTEM.BIN`. Сборка вычисляет фактический размер образа в секторах и передаёт
bootloader-у точное число секторов C-части после 16-секторного ASM-entry;
96 секторов остаются проверяемым максимумом, а не фиксированным объёмом чтения.

Список собираемых программ находится в `$programNames`:

```powershell
$programNames = @(
    "shell",
    "print",
    "gui",
    "editor",
    "ls",
    "cat",
    "js",
    "poweroff"
)
```

`JS.BIN` собирается один раз из `pm32/user/js/js.c`, который подключает модули
из своего каталога. При формировании FAT тот же
бинарник добавляется второй записью `JSGUI.BIN`: первая запись имеет
`AppType = 0`, вторая — `AppType = 1`. Это временный способ запускать один
runtime с разными правами, пока тип JS-приложения хранится в FAT, а не в
манифесте скрипта.

Скрипты из `pm32/js_scripts` не компилируются. `build32.ps1` читает их как
обычные байты и добавляет в корень образа под именами FAT 8.3.

### Формирование FAT32

Массив `$files` описывает записи корневого каталога. Каждая запись содержит:

- `Name` — точное 11-байтное имя FAT 8.3;
- `Data` — байты файла;
- `AppType` — `0` для console и `1` для GUI.

Сейчас `GUI.BIN`, `EDITOR.BIN` и `JSGUI.BIN` имеют тип GUI. Переход из
начального shell в `GUI.BIN` является специальным `exec` PID 0; остальные
команды shell запускаются дочерними процессами через `sys_run`.

Скрипт вычисляет `FirstCluster` и `ClusterCount`, строит две копии FAT,
directory entries и копирует данные файлов в образ. Имя итогового образа можно
переопределить переменной окружения `MYOS_IMAGE`.

## `run32.ps1`

Скрипт сначала вызывает `build32.ps1`, затем запускает полученный образ в QEMU:

```powershell
.\run32.ps1
```

Используется SDL-дисплей со скрытым курсором Windows. Освободить захват мыши
можно правым Ctrl согласно параметру `grab-mod=rctrl`.

## `tools/make_icon.ps1`

Скрипт создаёт `pm32/assets/shell-icon.png` из исходного изображения:

1. вырезает заданную область;
2. масштабирует её до 48×48;
3. заменяет пурпурный фон прозрачностью;
4. формирует RGBA scanlines с PNG-фильтром 0;
5. создаёт один несжатый DEFLATE-блок;
6. вычисляет Adler-32 и CRC32;
7. записывает PNG chunks `IHDR`, `IDAT` и `IEND`.

Минимальный PNG-декодер GUI поддерживает именно этот ограниченный формат.
Если включить обычное PNG-сжатие или другие фильтры, GUI не сможет прочитать
иконку без расширения декодера.
