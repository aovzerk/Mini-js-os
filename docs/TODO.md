# План развития MyOS

Этот список описывает известные задачи текущей реализации. Завершённый пункт
следует переносить в соответствующий документ архитектуры или API, а не
оставлять здесь как описание уже работающей функции.

## P0 — стабильность

- [ ] Исправить безопасное завершение дочернего GUI-процесса и гарантировать
  возврат в сохранённый контекст GUI-сервера PID 0.
- [ ] Добавить IDT и минимальные обработчики `#UD`, `#GP`, `#PF` и double fault,
  чтобы ошибка приложения не перезапускала всю ОС.
- [ ] Добавить проверку сборки, запрещающую пользовательский BIN размером больше
  `0xE000` байт: с адреса `0x2E000` начинаются аргументы процесса.
- [ ] Автоматизировать QEMU smoke-тесты текстового shell, GUI-терминала,
  `JSTEST.JS`, `APITEST.JS` и `MONITOR.JS`.

Критерий P0: все перечисленные сценарии работают без `check_exception` и
`Triple fault`, а ошибка пользовательской программы завершается диагностикой.

## P1 — JavaScript как основной язык

- [ ] Завершить единый тип `Value`: number, boolean, string, object, null и
  код ошибки без специальных глобальных переменных вроде `result`.
- [x] Сделать API-функции возвращающими значения. `readFile`, `listFiles`
  и `terminalRead` возвращают динамические строки и не печатают их неявно.
- [ ] Завершить общую объектную модель. Литералы, числовые/строковые свойства и
  `console.log(object)` уже работают, но `myos`, `window` и `ProcessInfo` всё
  ещё обслуживаются специальными ветками runtime.
- [x] Добавить пользовательские и стрелочные функции, параметры всех
  реализованных типов, `return` и освобождаемые локальные области видимости.
- [x] Добавить обычные массивы, смешанные вложенные значения, `length` и
  индексирование.
- [ ] Добавить строковые выражения, конкатенацию и сравнение строк.
- [ ] Добавить `break`, `continue` и корректное короткое вычисление `&&`/`||`.
- [ ] Поддержать многострочные выражения и блоки без правила «оператор на одной
  строке».
- [ ] Добавить понятные ошибки с именем файла, строкой и столбцом.
- [x] Заменить фиксированные строковые слоты на ограниченный процессный heap.
- [ ] Определять console/GUI-права JS-приложения через манифест или заголовок
  скрипта и отказаться от двух FAT-записей `JS.BIN`/`JSGUI.BIN`.

Целевой API графического приложения:

```js
const myos = require("myos")
const window = myos.createWindow({ title: "Monitor" })
const processes = myos.listProcesses()

window.clear()
window.write(processes)
window.onKey(key => {})
window.run()
```

## P1 — процессы и GUI

- [x] Перенести desktop/taskbar/window policy на JavaScript. `desktop.js` рисует
  фон, launcher-иконки, основу taskbar, запуск приложений, маршрутизацию клавиш
  и курсор; `windows.js` обслуживает список окон, z-order, minimize/close,
  drag только за title bar при зажатой ЛКМ и terminal snapshot. C остаётся
  native framebuffer/input backend и не задаёт внешний вид desktop.

- [ ] Добавить в записи `listProcesses()` использование памяти процесса.
- [x] Добавить монотонные PIT-часы и кооперативные `setTimeout`, `setInterval`,
  `clearTimeout` и `clearInterval`.
- [ ] Завершить событийную модель без busy-loop. Kernel IPC использует очередь
  на 16 событий для клавиатуры и мыши, но JS пока опрашивает её через
  `pollEvent()`.
- [x] Убрать прямой доступ GUI-программ к PS/2: IRQ1/IRQ12 и packet queues
  принадлежат ядру, GUI получает ввод только через `sys_input_read`.
- [ ] Убрать прямой доступ GUI-сервера к VBE/PCI I/O и снизить IOPL с 3.
- [ ] Сделать число окон динамическим или увеличить текущий лимит 3.
- [ ] Добавить фокус, изменение размера окна и корректное завершение по кнопке
  закрытия.
- [ ] Убрать дублирование кода запуска терминала между кликом по иконке и
  клавишей `T`.

Физическая консоль уже имеет scrollback на 64 строки с `Page Up`/`Page Down`,
а JS-окна — атомарные `beginUpdate()`/`endUpdate()` без мерцания.

## P2 — планировщик и память

- [x] Добавить PIT 1000 Гц и вытесняющий round-robin планировщик с квантом
  10 мс; `sys_yield` оставить необязательной оптимизацией.
- [ ] Разделить kernel/user mappings; сейчас page directory использует слишком
  широкие identity mappings с пользовательским доступом.
- [ ] Добавить allocator физических страниц вместо фиксированных восьми слотов
  по 256 КБ.
- [ ] Проверять все пользовательские указатели и длины в syscall dispatcher.
- [ ] Сохранять полный контекст процесса, включая дополнительные регистры и
  состояние FPU при его появлении.
- [ ] Добавить состояния процесса `READY`, `RUNNING`, `WAITING`, `ZOMBIE`.

## P2 — файловая система

- [ ] Читать полные FAT-цепочки вместо предположения contiguous allocation.
- [ ] Поддержать каталоги и больше 16 root entries.
- [ ] Убрать фиксированную область новых файлов с кластера 400.
- [ ] Реализовать освобождение и повторное использование кластеров.
- [ ] Добавить удаление и переименование файлов.
- [ ] Возвращать точные коды ошибок файлового API.
- [ ] Проверять обе FAT и root directory после тестов записи автоматически.

## P3 — инструменты и документация

- [x] Разделить описание C-приложений и JS-приложений на отдельные документы.
- [x] Добавить подробные справочники функций ядра, syscall ABI и JS API с
  типами входов/выходов, объектами, ограничениями и примерами.
- [ ] Генерировать таблицу syscall из единого источника, чтобы номера в
  `api.h`, `gui.h`, `core/dispatch.c` и `docs/syscalls.md` не расходились.
- [ ] Добавить команду сборки только образа и команду запуска диагностического
  QEMU без копирования длинных параметров.
- [ ] Добавить проверку FAT 8.3 имён, числа root entries и пересечений кластеров
  непосредственно в `build32.ps1`.
- [ ] Добавить версии ABI ядра и JS-модуля `myos`.
