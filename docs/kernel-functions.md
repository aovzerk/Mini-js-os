# Функции и подсистемы ядра

Это карта внутренних функций ядра. Они не являются пользовательским API:
приложения должны обращаться к ним только через syscall из `api.h`/`gui.h`.

## Загрузка и вход в ядро

| Функция/точка | Вход | Выход и эффект |
|---|---|---|
| `protected_start` | управление от boot loader в real mode | GDT, PIC, PIT, PS/2, IDT, TSS, paging; запуск PID 0 в CPL3 |
| `kernel_dispatch(KernelRequest *)` | trap frame запроса | результат и контекст процесса для `IRETD` |
| `kernel_dispatch_impl` | заполненный `KernelRequest` | маршрутизация syscall или внутреннего запроса |
| `irq0_entry` | IRQ PIT | часы; каждые 10 ms возможное вытеснение ring 3 |
| `irq1_entry` | IRQ клавиатуры | байт в keyboard ring buffer |
| `irq12_entry` | IRQ мыши | вычитывает доступные AUX-байты, собирает полные пакеты |

IRQ12 за один вход читает до 16 байтов, пока `status.OBF=1` и
`status.AUX=1`. Это важно: если оставить байты пакета в общем PS/2 output
buffer, линия IRQ может остаться активной и новые движения перестанут давать
фронты. Клавиатурный байт IRQ12 не забирает.

## Процессы и планирование

| Функция | Вход | Результат |
|---|---|---|
| `make_address_space(pid)` | PID `0..7` | page directory/table и mappings процесса |
| `spawn_command(command)` | строка команды | новый PID либо отрицательный код |
| `execute(command)` | строка | замена image текущего процесса |
| `switch_process(request, next)` | текущий frame и PID назначения | сохраняет старый и формирует новый контекст |
| `schedule(request)` | frame прерванного процесса | следующий runnable PID по round-robin |
| `fill_process_info(to, pid)` | выходная структура и PID | публичный snapshot процесса |

PIT работает на 1000 Гц, квант равен 10 тикам. `sys_yield` лишь досрочно
запускает `schedule`; корректность многозадачности от него не зависит.
Состояния пока представлены комбинацией `active`, `waiting_child`,
`sleeping_until`, а не отдельным enum.

## Память

| Функция | Вход | Результат |
|---|---|---|
| `heap_alloc(size)` | число байтов | обнулённый блок heap текущего PID или `NULL` |
| `heap_free(pointer)` | адрес начала выделенного блока | освобождение с обнулением, код результата |
| `heap_reset(pid)` | PID | освобождение всех блоков завершившегося процесса |
| `make_address_space(pid)` | PID | изоляция пользовательского image/heap/stack |

Пользовательский image начинается с `0x400000`, heap — с `0x500000`, вершина
stack — `0x600000`. Ядро обращается к физической памяти процессов через
supervisor-only alias, а не через GUI backbuffer `0x800000`.

## Файловая система

| Функция | Вход | Результат |
|---|---|---|
| `load_file(name, destination, capacity)` | FAT 8.3, буфер, ёмкость | размер или ошибка; не переполняет буфер |
| `write_file(name, source, size)` | FAT 8.3 и байты | записанный размер или ошибка |
| `list_files(buffer, capacity)` | текстовый буфер | длина списка root directory |
| ATA PIO helpers | LBA/сектор | чтение/запись 512 байт через `0x1F0..0x1F7` |

Текущие ограничения: только root directory, короткие FAT 8.3 имена,
ограниченная запись и предположение о непрерывном размещении читаемого файла.

## Ввод

`input/ps2.c` владеет адресами и операциями ring buffer. `input/keyboard.c`
преобразует scan-коды с Shift/extended state. `input/mouse.c` принимает только
полные трёхбайтовые пакеты, объединяет накопившееся движение и сохраняет
последнее состояние кнопок.

Путь события мыши:

```text
IRQ12 -> AUX drain -> packet ring -> mouse_read_packet()
      -> sys_input_read() -> GUI server -> GuiEvent -> JS pollEvent()
```

## Консоль и GUI

`drivers/vga_console.c` реализует низкоуровневый VGA text driver:
`console_init`, `console_write`, курсор и scrollback. Приглашение и команды
принадлежат `SHELL.BIN`, а не драйверу.

GUI PID 0 владеет VBE framebuffer и backbuffer. `native_backend.c` принимает
retained draw-команды процессов, хранит committed-слои и объединяет несколько
`PRESENT` в один программный кадр. Обработка очереди ограничена бюджетом, чтобы
производитель команд не вытеснил ввод. Курсор является атомарным примитивом
`GUI_DRAW_CURSOR`: положение и время рисования задаёт JS, растеризацию делает
backend.

## Правила изменения ядра

1. Не обращаться к пользовательскому указателю без проверки диапазона.
2. IRQ должен сохранить все изменяемые регистры и отправить EOI нужным PIC.
3. PS/2 status нужно читать до data; keyboard и AUX нельзя смешивать.
4. Нельзя выполнять неограниченный цикл над очередью, которую пополняет другой
   процесс или IRQ.
5. Изменение `KernelRequest`, `GuiDrawCommand` или `GuiEvent` является
   изменением ABI и требует обновления документации и обеих сторон вызова.
